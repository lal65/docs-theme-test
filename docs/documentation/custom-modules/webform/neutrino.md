## Summary
This submodule provides a specialized composite element type that enriches
form submission data through a third party data and validation service.

## Neutrino composite element type
This custom webform element is unique in that its schema reacts to the form
that the element is placed on. For every email or phone number element that
exists on the form, a series of enrichment fields are added to the neutrino
element.

For example, if a form has two elements: `email` and `phone`, the Neutrino
element will have child fields of `email_{data point}` and
`phone_{data point}`, where the name of the field being enriched is separated
from the data point with an underscore.

This allows the Neutrino element type to work on every form regardless of its
shape or size. Unlimited email and phone number elements are supported, and
the predictable nomenclature allows for new external integrations to be set
up without any code on the application side.

### Phone number enhancements

For phone number elements, the following data points are collected:

| Parameter                  | Type    | Description                                                                                                                                                  |
|----------------------------|---------|--------------------------------------------------------------------------------------------------------------------------------------------------------------|
| valid                      | boolean | Is this a valid phone number                                                                                                                                 |
| type                       | string  | The number type based on the number prefix.<br>Possible values are:<br>mobile<br>fixed-line<br>premium-rate<br>toll-free<br>voip<br>unknown (use HLR lookup) |
| international_calling_code | string  | The international calling code                                                                                                                               |
| international_number       | string  | The number represented in full international format (E.164)                                                                                                  |
| local_number               | string  | The number represented in local dialing format                                                                                                               |
| location                   | string  | The phone number location. Could be the city, region or country depending on the type of number                                                              |
| country                    | string  | The phone number country                                                                                                                                     |
| country_code               | string  | The phone number country as an ISO 2-letter country code                                                                                                     |
| country_code3              | string  | The phone number country as an ISO 3-letter country code                                                                                                     |
| currency_code              | string  | ISO 4217 currency code associated with the country                                                                                                           |
| is_mobile                  | boolean | True if this is a mobile number. If the number type is unknown this value will be false                                                                      |
| prefix_network             | string  | The network/carrier who owns the prefix (this only works for some countries, use HLR lookup for global network detection)                                    |

See the [phone validate](https://www.neutrinoapi.com/api/phone-validate/) API
documentation for more details.

This strategy allows for a very permissive user experience when it comes to
entering phone numbers. Users may enter phone numbers in local format,
international format, and even in some cases "oddly formatted" input and the
API service will perform fuzzy matching and validation to produce the
appropriate [E.164](https://en.wikipedia.org/wiki/E.164) formatted number in a
normalized fashion. Part of the reason why this system was created was to keep
the user experience very friendly when collecting phone numbers, as to not
inadvertently creating a barrier, while at the same time providing normalized
data for the CRM system. This best of both worlds approach is a critical part
of data quality assurance.

### Downstream processing opportunities
Any of these data points may be used to intelligently handle downstream
processing tasks. For example, if a particular form wanted to send a
possible spam notification if a submission occurs with an email that has
tripped a blocklist sensor, that would be possible via a handler with a
condition set up to observe the `domain_blocklists` element value.

The Salesforce CRM system also ingests the E.164 formatted phone number for
information request submissions rather than what the end-user entered into the
form.

## Requirements
This module requires the custom Webform and the contributed
[Neutrino API](http://drupal.org/project/neutrino_api) modules.

## Installation
Install as you would normally install a contributed Drupal module. For further
information, see
[Installing Drupal Modules](https://www.drupal.org/extending-drupal/installing-drupal-modules).

## Configuration
This module does not expose any configuration.
